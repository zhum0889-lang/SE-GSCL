# 18 域 LLM 完整诊断实验说明

## 1. 实验目的

本实验检验 LLM 是否真正提升跨工况故障诊断，而不是简单复述小模型输出。预训练 LLM 已具备通用语言知识，本阶段不从头训练全部参数，而是在保持主体参数稳定的前提下，充分训练连续提示适配器，并设置受控的 LoRA 版本以评估有限参数更新能否进一步增强工程语义理解。

主实验采用 18 个互不重叠的复合域和三个随机种子。训练按 D1 至 D18 的顺序持续接收新工况，测试标签只在推理结束后用于计算指标，不能参与提示适配、LoRA 更新或模型选择。

## 2. 完整数据链路

1. P1 轻量信号专家在 18 域序列上持续更新，输出故障身份后验和信号表示。
2. P2 构造局部症状语义并进行可靠性融合，同时导出转速、采样率、扭矩和径向载荷等可观测工况。缺失属性使用零值和缺失掩码共同表示，不输入域编号或故障标签。
3. P3 将连续工程语义映射为 LLM 词嵌入空间中的提示 token，由预训练 LLM 直接生成故障类别。
4. 诊断锁定后，LLM 生成故障原因、支持证据、反证、不确定性和维护建议，避免解释阶段反向改变诊断。

由于当前数据尚未核实 6204、N204/NJ204 和 30204 三类轴承的完整运动学参数，18 域 LLM 主实验使用类别监督的局部症状语义，不伪造 BPFO/BPFI 软标签。物理引导分支应在获得轴承几何参数后作为独立实验补充。

## 3. LLM 对照设置

- `continuous_identity_only`：仅输入小模型的连续故障身份及可靠性，检验 LLM 对模糊类别关系的处理能力。
- `continuous_no_condition`：增加局部症状语义，不提供工况上下文。
- `continuous_full`：在冻结 LLM 下同时输入故障身份、局部症状、融合后验、不确定性和可观测工况。
- `continuous_full_lora`：先加载冻结 LLM 阶段已经收敛的完整连续提示，再联合更新提示适配器和注意力层 LoRA；LLM 主体仍保持冻结。

四组实验使用相同源域训练样本、验证样本和 18 域测试样本。连续提示最多训练 30 个 epoch，并按源域验证损失提前停止。LoRA 阶段从冻结 LLM 的完整提示检查点初始化，只更新提示适配器以及 `q_proj` 和 `v_proj` 的低秩参数。这一渐进式过程用于降低随机提示与 LoRA 同时更新造成的梯度干扰。

## 5. 结果文件

汇总结果位于：

`results/paper_matrix/summary/multidomain8_disjoint18/llm/`

主要文件包括：

- `p3_llm_summary.csv`：四种 LLM 设置的三随机种子均值和标准差。
- `p3_llm_by_seed.csv`：每个随机种子的准确率、纠错率和显著性结果。
- `p3_llm_by_domain.csv`：18 个域上的 LLM 与小模型对比。
- `p3_llm_analysis.json`：便于自动分析的完整汇总。
- `p3_llm_accuracy_and_correction.png`：小模型、融合结果和 LLM 的准确率及纠错/破坏率图。

## 6. 结论判定规则

只有同时满足以下条件，才能声称 LLM 提升了诊断能力：

1. LLM 平衡准确率高于层次融合基线，并在三个随机种子上方向一致。
2. LLM 纠正的小模型错误数量高于其新增错误数量，即纠错率高于破坏率。
3. 各随机种子分别进行配对 McNemar 精确检验；不平均 p 值，而是报告显著种子数和最保守的最大 p 值。提升还不能只由单个域或单一类别驱动。
4. `full` 优于 `no_condition`，才能说明工况上下文有实际贡献。
5. `full_lora` 优于 `full`，才能说明 LoRA 适配具有额外价值；否则应保留冻结 LLM，以降低计算和过拟合风险。

最终论文应同时报告准确率、平衡准确率、三随机种子标准差、逐域结果、纠错率、破坏率和配对显著性，不能只报告最优单次运行。
